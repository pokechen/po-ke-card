## 1. 作品简介

章鱼牌是一款昆特牌式（三局两胜、弃牌留牌、阵营 + 主将技能）的策略卡牌对战游戏，已上线微信小游戏并配套腾讯云 CloudBase 云函数后端。它拥有 **254 张** 历史人物 / 技能 / 时局卡牌，覆盖多个阵营与可成长的主将技能体系。

与"传统卡牌游戏 + 一个会出牌的机器人"不同，章鱼牌的设计起点就是 **AI 原生**：

- 玩家的对手不是一个脚本 bot，而是一个基于**多目标局面评估**做决策的 AI 策略体；
- 牌组不是预先写死的，而是由 **AI 程序化组牌** 按联动关系自动生成；
- 难度不是写死的几档，而是用一组 **AI 性格参数** 连续可调，并随玩家段位 **动态进化**；
- 每一局天然产出的结构化战报，可作为 **大模型叙事输入**，生成涌现式对战故事。

我们用工程中可复现的 **100 场自动对战验证闭环** 来保证 AI 策略的真实胜率与收敛性——这正是赛题所倡导的 "AI 原生游戏的工程化落地路径"。

## 4. AI 原生设计理念：为什么是 AI 原生，而非 AI 辅助

赛题明确反对 "AI 仅作为辅助工具"。我们用一张对照表说明章鱼牌的 AI 原生定位：

| 维度 | 传统做法（AI 辅助） | 章鱼牌（AI 原生） |
|---|---|---|
| 对手 | 固定脚本 / 规则树 | 多目标启发式决策体，能权衡"该认输留牌还是冒险翻盘" |
| 组牌 | 策划手填卡组 | AI 程序化组牌，按联动关系自动生成合法牌组 |
| 难度 | 写死几档 | 四维性格参数连续可调 + 随段位动态进化 |
| 内容 | 静态卡面 | 结构化战报驱动涌现式叙事 |
| 验证 | 人工试玩 | 100 场自动对战 + 胜率统计 + 不收敛熔断 |

**核心主张**：在章鱼牌里，去掉 AI，游戏就不存在——玩家没有可对抗的智能体、没有可生成的牌组、没有可调的难度曲线。AI 是游戏的"操作系统"，不是"插件"。

## 5. AI 玩法设计（核心章节）

### 5.1 AI 对手决策引擎（已落地）

核心函数：`aiDecideTurnDocumentV2`（位于共享战斗核心 `shared/core/battle.js`）。

它不是 `if (score > x) play(...)` 的脚本，而是一个**局面分析 + 多目标评估**的启发式引擎：

```
决策 = f(可见局面评分前/后, 即时净摆动, 保留资源价值, 可见反制风险, 过度投入惩罚)
```

- **可见局面评分**：对当前双方场上、手牌、牌库剩余价值做加权估计。
- **即时净摆动（immediateNetSwing）**：打出某张牌能带来的分数变化。
- **保留资源价值（preservedResourceValue）**：评估"这回合不出这张牌、留到下局"的价值，这是昆特式玩法的精髓——好 AI 懂得"认输留牌"。
- **可见反制风险（visibleCounterRisk）**：预判对手可能的清场 / 翻倍等反制。
- **过度投入惩罚（overcommitPenalty）**：避免一波打空导致后续局崩盘。
- **Top3 候选动作**：引擎会输出排序后的前 3 个候选决策，既用于内部择优，也可在 UI 上做"AI 思考过程"可解释展示。

**可解释性亮点**：对战记录天然采用 `玩家打出「卡牌名」 → 能力名：生效结果` 的标准化格式（例如 `玩家打出「孟尝君」 → 集贤：孟尝君x2`）。这既是对战回放的数据基础，也是 AI 决策过程可被玩家"读懂"的窗口。

### 5.2 AI 动态难度与参数化人格（已落地，作为 DDA 基础）

核心配置：`AI_DIFFICULTY`（位于 `shared/core/battle.js`）。

```js
const AI_DIFFICULTY = {
  easy:   { blunder: 0.45, concede: false, valueNoise: 8, minLeadToStop: 99 },
  normal: { blunder: 0.10, concede: true,  valueNoise: 2, minLeadToStop: 5  },
  hard:   { blunder: 0,    concede: true,  valueNoise: 0, minLeadToStop: 1  },
};
```

这 4 个参数本质是 **AI 的"性格旋钮"**，也是动态难度调节（DDA）的连续控制面：

| 参数 | 含义 | 对"人格"的影响 |
|---|---|---|
| `blunder` | 失误概率 | 高 = 莽撞新手，低 = 沉稳老手 |
| `concede` | 是否会在领先时主动占位（认输留牌） | 是否懂得战略性放弃 |
| `valueNoise` | 估值噪声 | 高 = 判断飘忽，低 = 精准算计 |
| `minLeadToStop` | 领先多少才停手 | 决定侵略性边界 |

**与排位赛的结合（已落地）**：排位赛 7 个段位（平民 → 帝王）按段位动态放大 AI 难度——低段位用简单 AI 且失败不扣权势保护新手，高段位用困难 AI，最高段位额外强制玩家随机阵营与自动组牌，防止固定强势卡组刷榜。这是 **AI 难度随玩家成长而进化** 的真实落地。

> **AI 原生映射**：难度不是策划写死的档位，而是由一组可连续调节的 AI 性格参数驱动；玩家在排位赛中实际是在和一个"随自己段位变强"的智能体对弈。

### 5.3 AI 程序化组牌（已落地 — 程序化内容生成）

核心函数：`selectAutoDeckCards` / `buildDeck`（位于 `shared/core/cards.js`）。

在 254 张卡库中，AI 不是随机抽卡，而是：

1. **联动组识别**：基于 `Tight Bond`（紧密联结）、`Muster`（召集）、`Berserker`（狂战）、`Summon`（召唤）等能力把卡牌聚类成 synergy group；
2. **价值排序**：用 `autoDeckCardValue` 对卡牌打分（人物基础战力 + 能力加分 + 联动加成），特殊牌（如"请辞归隐"=诱饵、"破釜沉舟"=玛德罗梅）按牌组上下文动态赋权；
3. **难度画像**：难度越高，牌组越"小而精"（例如困难档采用 22 单位 / 4 特殊的小牌组强策略，经 100 场验证胜率 60%）；
4. **合法性约束**：英雄数量、间谍牌数量、单组携带上限等自动收敛，保证生成的牌组始终合法可玩。

对玩家而言，选择"自动组牌"即可获得一套由 AI 基于当前阵营与难度画像生成的高质量牌组；对 AI 对手而言，其牌组同样由该引擎生成——**组牌这一环节完全由 AI 承担**。

### 5.4 AI 策略的工程化验证闭环（已落地 — 对应"工程化落地路径"）

赛题鼓励"验证 AI 原生游戏的工程化落地路径"。章鱼牌内置一套**可复现的 AI 验证框架**：

- `scripts/simulate-ai-matches.js`：让新旧 AI 策略进行 **100 场 "随机卡牌 + 困难难度" 对战**，交替先后手，统计新 / 旧策略胜场与平局，得出新策略胜率。
- `scripts/test-ai-strategy.js`：针对具体卡牌交互（如诱饵医疗兵 `verify-decoy-medic.js`）做单元级策略验证。
- **不收敛熔断规则**：单场模拟 `maxSteps` 超过硬上限即判定为战斗核心死循环 bug（如某回合永远走不到"双方都 pass"），必须修复而非调大上限。这是线上对局稳定的硬保险。

这套闭环确保：**任何 AI 策略改动都必须用数据说话**——只有新策略胜率高于旧策略才切换为正式策略，否则保留旧策略并分析原因（停牌时机、资源保留、目标选择等）。这正是 AI 原生游戏从"能跑"到"可信"的engineering baseline。

### 5.5 规划方向：AI 主将 NPC 长线情感连接（呼应特邀赛道 1）

主将（Leader）目前是每局携带一个主动技能的战略单位。规划将其升级为 **可长期养成的 AI 队友 NPC**：

- **长期记忆**：跨对局的战绩、常用卡组、偏好打法沉淀为主将的"记忆"，影响其对玩家的建议语气与出战风格。
- **性格定制**：用 `AI_DIFFICULTY` 同款的性格参数 + 少量提示词，让不同主将呈现不同性格（沉稳 / 激进 / 谨慎），并建立玩家对特定主将的长期追求。
- **一致性（Consistency）**：通过"记忆摘要 + 人设锚点"约束，缓解长线交互中的人设漂移与"记忆膨胀"幻觉——以结构化战报作为记忆的可靠事实源，而非让模型自由发挥。

### 5.6 规划方向：AI 战报涌现式叙事（呼应特邀赛道 2）

每一局对战产出的标准化战报（`玩家打出「卡牌名」 → 能力名：生效结果` + 小局比分 + 召唤 / 复归 / 摧毁等事件）是一个**天然的事件流**。规划将其作为大模型输入：

- 把一局的结构化事件流喂给叙事模型，生成"这一局发生了什么故事"的涌现式战报（例如把一次翻盘描写成主将的绝地反击）。
- 通过明确的玩法框架（三局两胜的胜负目标）解决 AI 叙事常见的"目标感缺失 / 反馈滞后"——玩家始终有清晰的胜负锚点，叙事只是对"已发生的真实对局"的再表达，而非凭空生成，避免"社会学实验"式的枯燥。

> 这两个规划方向把"AI 原生"从对战核心延伸到**角色交互**与**世界叙事**，使作品具备从开放赛道辐射到两个特邀赛道的整体性，但并非本次提交的硬性依赖。

## 6. 核心玩法规则（玩家实际可玩内容）

| 机制 | 说明 |
|---|---|
| 对战结构 | 三局两胜（best of 3），每局独立计分，先赢 2 局者胜。 |
| 核心循环 | 出牌加战力 → 一方认输（pass）→ 比分结算 → 剩余手牌带入下局（留牌博弈）。 |
| 阵营 | 多阵营可选（如北方领域、怪物等），不同阵营有专属卡池与风格。 |
| 主将技能 | 每局一次主动技能（如时局牌检索、弃牌换牌、翻倍某阵线），是战术转折点。 |
| 卡牌规模 | 254 张，含人物、英雄、特殊（诱饵 / 天晴 / 号令 / 焚毁）、时局（天气）四类。 |
| 能力体系 | 集贤、出使、传世、济世、鼓舞、召唤、紧密联结、召集、狂战、间谍等，组合产生深度策略。 |
| 模式 | 单机（vs AI）/ 联机（vs 真人，PVP 共享核心保证公平）/ 排位赛（vs AI 天梯）。 |

**10 分钟以上玩法容量（满足作品要求）**：一局三局两胜通常 5–10 分钟；排位赛的段位晋升、威望积累、排行榜竞争、卡组自定义（我的牌组）与历史战绩复盘，提供了远超过 10 分钟的持续可玩内容。

## 7. 产品架构与技术实现（简）

```
微信小游戏客户端 (Canvas)
   │ 共享战斗核心 shared/core/*（单机/联机/排位共用，避免双份逻辑）
   ▼
CloudBase 云函数 pvpRoom / adminStats (Node.js 18)
   │ 排位档案、对局校验、排行榜、轻量反作弊
   ▼
CloudBase 数据库 (rank_profiles / rank_matches / users / match_history ...)
```

- **共享核心同步**：修改 `shared/core/*` 后通过 `scripts/sync-pvp-core.js` 自动复制进云函数目录，并校验卡牌数量 254，保证客户端与云端逻辑一致。
- **轻量反作弊**：排位结算由云端权威计算权势 / 威望 / 段位；最高段位云端强制随机阵营与自动组牌，不信任客户端选择；异常对局标记 `suspicious` / `invalid`，不计入排行榜与胜负统计，仅在管理端异常报表中展示（无异常则不展示该模块）。
- **隐私保护**：排行榜与公开资料不返回 OpenID、Token 等敏感信息。

## 8. 游戏创意点与独创性

1. **AI 作为"发动机"而非"对手皮肤"**：决策、组牌、难度、叙事四环均由 AI 承担，去掉 AI 游戏即停摆。
2. **可解释的 AI 决策**：Top3 候选动作 + 标准化战报，让玩家"看懂"AI 在想什么，把黑盒对手变成可学习的对手。
3. **随玩家成长的 AI 难度曲线**：段位越高，AI 性格参数越逼近"沉稳老手"，且最高段位反制玩家固定套路——动态 DDA。
4. **程序化内容生成**：254 张卡库由 AI 按联动关系实时组装合法牌组，内容是"生成"的而非"罗列"的。
5. **工程化可信 AI**：100 场自动对战 + 胜率统计 + 不收敛熔断，把 AI 策略迭代建立在数据与稳定性之上。
6. **真实运营级完整度**：已上线、含排位 / 排行榜 / 管理端反作弊，不是 Demo 玩具，而是可长期运营的 AI 原生产品。

## 9. 用户体验流程（一局示意）

1. 首页选择「单机对战 / 联网对战 / 排位赛」。
2. 准备页：选阵营、主将、自定义或**AI 自动组牌**。
3. 对局：与 AI 决策体博弈，长按卡牌看详情、长按主将看技能。
4. 结算：展示小局比分、`玩家打出「卡牌」→ 能力：结果` 战报、段位 / 权势 / 威望变化。
5. 排位赛：赢 1 局 +1 权势冲击段位，排行榜查看全服 Top 玩家。
6. 历史：复盘每一局的真实对战记录。

## 10. 公平性与反作弊（AI 不垄断、人不被坑）

- AI 对手与玩家使用**同一套战斗核心**，不存在 AI 专属特权数值。
- 排位结算权势 / 威望 / 段位**全部由云端计算**，客户端只展示。
- 轻量校验覆盖：对局超时、重复提交、最高段位自定义牌组、结果与小局矛盾、威望越限等，异常局不生效、不计入统计。

## 14. 附录：关键术语

- **AI 原生（AI-native）**：AI 是游戏运转的核心机制，而非附加功能。
- **DDA（动态难度调节）**：根据玩家表现实时调整 AI 强度。
- **程序化组牌**：由 AI 按规则 / 联动自动生成合法牌组。
- **不收敛熔断**：单场模拟超步数即判死循环，强制修复战斗核心。
- **排位赛 7 段位**：平民 / 士卒 / 校尉 / 都督 / 将军 / 诸侯 / 帝王，对应 AI 难度由简单到困难。
