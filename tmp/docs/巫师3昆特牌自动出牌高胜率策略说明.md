# 《巫师3：狂猎》昆特牌自动出牌高胜率策略说明

> 文档用途：供自动出牌程序实现策略逻辑。  
> 适用范围：《巫师3：狂猎》本体及 DLC 内置的单机昆特牌小游戏，不适用于独立游戏《GWENT: The Witcher Card Game》。  
> 明确边界：牌组、领袖和开局手牌均已由外部系统确定；本文只规定拿到手牌后的出牌、目标选择、领袖使用和停牌逻辑，不讨论组牌、换牌或牌组优化。  
> 一期边界：不知道对手完整手牌和牌库，不使用历史对局、NPC 个体画像或训练模型，只根据当前可见局面决策。  
> 调研日期：2026-07-21。

## 1. 目标与结论

### 1.1 优化目标

程序的最终目标必须是：

```text
最大化整场比赛获胜概率 P(match_win)
```

不要把“当前回合分数最大”当作目标。昆特牌通常通过最多三轮消耗双方的 2 枚生命宝石，手牌贯穿整场；主动放弃一轮并换取牌差，通常比高成本赢下该轮更有价值。

### 1.2 最重要的策略结论

按重要性排序：

1. 优先制造和保持手牌优势；如果当前手牌中有间谍，应优先评估其抽牌收益。
2. 第一轮通常先使用间谍、低风险单位和未来价值较低的单位。
3. 当公开局面显示对手已经比己方投入更多资源时，允许主动放弃非决胜轮，保留后续资源。
4. 对手已经停牌时，用最少的未来资源损失取得刚好足够的领先，不追求大比分。
5. 诱饵优先回收对手打到己方场上的间谍，其次回收医生或有高价值入场效果的单位。
6. 医生优先复活间谍，其次补齐紧密联结，再次是高收益入场单位和高点单位。
7. 灼烧、天气、号角和紧密联结应根据当前可见局面完整结算后的净收益决定，避免只按卡面强度判断。
8. 对手为怪物且己方手中已有刺骨冰霜、灼烧或 Villentretenmerth 时，应提高这些牌的保留和使用优先级，用于反制已出现或正在形成的近战召集铺场。
9. 一期采用“硬规则 + 当前可见状态模拟 + 对手停牌后的已知状态获胜序列搜索 + 保守风险控制”，不猜测对手具体隐藏牌。

### 1.3 一期决策边界

程序不知道对手完整手牌、牌库和 NPC 决策逻辑，因此一期不声称得到理论全局最优解，也不猜测对手具体持有什么牌。程序只使用以下信息：

```text
己方手牌、己方牌库剩余信息、己方弃牌堆
双方当前场面与分数
双方剩余生命宝石与停牌状态
对手手牌张数、阵营、领袖及已经公开或打出的牌
当前天气、号角、弃牌堆和公开的跨轮效果
```

一期以可解释、可复现的保守规则提高胜率。基于历史对局学习对手牌型、停牌倾向和个体 NPC 行为，统一放到二期扩展，不作为一期实现依赖。

### 1.4 社区攻略高胜率共识（2026-07-22 调研补充）

调研 Console Pulse《Witcher 3 Gwent Guide》等攻略，验证了上述结论并补充要点（与第 1.2 节一致）：

- **牌差优先于单轮比分**：攻略明确指出“两轮后手握两张牌的优势往往决定整场胜负”，这是最大胜率杠杆；主动放弃某轮保留手牌通常优于倾尽资源赢下该轮。
- **间谍（出使）单卡价值最高**：极小战力换 2 张手牌，净收益几乎总为正，应尽早用。
- **主动放弃非决胜轮是合法高明策略**：对手过度投入时早早 Pass，用更厚手牌进后续轮。
- **控制牌（天气/灼烧）只在净收益高且自伤可控时用**，避免误删己方核心。
- **领袖按收益随时用，不固定轮次**；选择应直接支持牌组主胜利条件。
- **按阵营调整节奏**：怪物每轮保留 1 单位、可故意输 R1；松鼠党每轮选先手（通常让对手）获信息/节奏；史凯利格 R3 召 2 随机单位、擅长拉长线；尼弗迦德平局算赢、容错高；北方领域赢轮抽牌易滚雪球。

> 以上来自公开攻略经验，不等同 NPC 算法；一期仍以第 4–5 章可见状态模拟 + 硬规则为准。

## 2. 必须实现准确的规则层

策略层必须调用统一的规则模拟器计算结果，不应在策略中重复硬编码点数。至少覆盖以下规则：

- 双方通常各有 2 枚生命宝石；输掉一轮失去 1 枚。普通阵营打平时双方各失去 1 枚；尼弗迦德的阵营能力会把平分轮判为尼弗迦德获胜。程序应直接记录双方剩余宝石，而不能只记录“胜轮数”。
- 当任一方宝石归零时，按实际游戏版本判定比赛终局；若平分导致双方同时归零，还必须明确程序所处环境把该结果视为平局还是玩家未获胜，不能自行猜测。
- 手牌由外部系统传入；策略模块不负责组牌或开局换牌。正常情况下每轮不会自动补充一套新手牌，只有间谍、阵营能力等效果会改变手牌。
- 单位分为近战、远程、攻城三排；敏捷单位可以在近战或远程中选择一个合法排，落位后不能自行移动。
- 停牌后，该轮不能继续出牌。
- 英雄牌免疫天气、灼烧和普通增减益，也不能被诱饵回收或被医生复活。
- 间谍打到对方场上，并让出牌方抽两张牌。
- 诱饵只能换回己方场上的合法非英雄单位。
- 医生从己方弃牌堆复活合法的非英雄单位，被复活单位的入场能力应正常结算，包括可能继续触发医生链或间谍抽牌。
- 召集会把同组的其余合法卡牌打到场上。不同资料对“手牌中的同组牌是否一并拉出”表述不完全一致，必须用目标游戏版本做固定测试，再写入规则清单；策略层只读取模拟器结果。
- 紧密联结按同名联结牌数量计算倍率，不是简单地对整个排固定翻倍。
- 士气鼓舞使同排其他可受益单位获得 +1，自身不吃自己的士气效果，英雄不受益。
- 号角对目标排可受益的非英雄单位翻倍；同一排号角效果不能重复叠加。
- 通用灼烧消灭全场当前战力最高的所有合法非英雄单位，可能同时消灭双方多张并列牌。
- Villentretenmerth 等单位型灼烧属于独立的“目标排 + 触发阈值”效果，必须由卡牌数据定义，不能复用通用灼烧的全场目标规则。
- 天气影响双方对应战斗排，英雄不受影响。可先以“天气把受影响单位的基础值置为 1，再应用联结、士气和号角”的顺序实现，但最终必须用实机固定局面验证每一步结果。
- 狂战士/Mardroeme、召唤复仇者等 DLC 能力必须作为独立效果处理；变形目标、触发时点、衍生牌来源和离场触发范围应进入版本化规则清单。
- 北方领域：赢下一轮后额外抽一张牌。
- 尼弗迦德：赢得平分轮。
- 怪物：每轮结束后随机保留一张单位到下一轮。
- 松鼠党的先手选择结果由外部系统传入；本文策略只读取 `currentPlayer`，不负责开局先手选择。
- 史凯利格：第三轮开始时，从弃牌堆随机复活两张符合资格的单位；英雄、衍生牌等是否属于候选集合必须按目标版本实测固化。

### 2.1 高风险实现点

以下错误会直接破坏策略判断：

1. 把独立版《GWENT》的规则混入《巫师3》内置昆特牌。
2. 把英雄牌当作可被号角强化、医生复活或诱饵回收。
3. 只烧掉一张最高单位，而不是烧掉所有合法的并列最高单位。
4. 忽略灼烧会烧到己方。
5. 忽略天气影响双方。
6. 错误计算三张紧密联结牌的倍率。
7. 对尼弗迦德仍按普通平局处理。
8. 忽略怪物跨轮保留单位和史凯利格第三轮复活。
9. 只记录卡牌所有者，不记录当前控制者和所在区域，导致敌方间谍、诱饵和弃牌堆归属错误。
10. 用“胜轮数”代替剩余生命宝石，无法处理普通阵营平分时双方同时失去宝石。
11. 把单位型灼烧当作通用灼烧，忽略目标排和触发阈值。

### 2.2 版本化规则清单

本说明文档定义的是决策策略，不应替代完整规则规格。实现时应维护机器可读的规则清单，每条规则标记：

```text
VERIFIED_IN_TARGET_BUILD    // 已在目标游戏版本固定局面验证
SUPPORTED_BY_MULTIPLE_SOURCES
SOURCE_CONFLICT
NEEDS_IN_GAME_TEST
```

至少为召集范围、平分终局、天气与联结/士气/号角顺序、史凯利格复活候选、狂战士变形、召唤复仇者和所有单位型灼烧建立固定测试。搜索器只能调用通过验证的规则模拟器；未验证规则不得由策略层自行猜测。

建议至少维护以下状态：

```text
GameState
  roundIndex                  // 1..3
  selfLivesRemaining          // 通常初始为 2
  opponentLivesRemaining
  selfRoundsWon               // 可作统计字段，不能代替 lives
  opponentRoundsWon
  lastRoundResult             // SELF_WIN/OPP_WIN/TIE
  matchResult                 // ONGOING/SELF_WIN/OPP_WIN/DRAW
  currentPlayer
  selfPassed
  opponentPassed

  selfFaction
  opponentFaction
  selfLeader
  opponentLeader
  selfLeaderAvailable
  opponentLeaderAvailable

  selfHand[]
  selfDeck[]                       // 由外部系统提供完整剩余己方牌，不在本文决定其组成
  selfDiscard[]
  opponentHandCount               // 一期只知道张数
  opponentRevealedCards[]         // 已经公开、打出或进入弃牌堆的牌
  opponentDiscard[]               // 公开信息
  // 不维护 opponentHiddenHand 或 opponentDeckContents

  selfBoard[close, ranged, siege]
  opponentBoard[close, ranged, siege]
  activeWeather[]
  rowHornState[]

  actionHistory[]
```

每张卡至少记录：

```text
Card
  id
  name
  owner
  controller
  zone                         // deck/hand/board/discard
  row
  baseStrength
  currentStrength
  isHero
  abilities[]
  musterGroup
  tightBondGroup
```

### 3.1 派生指标

每次决策前重新计算：

```text
scoreDelta            = selfScore - opponentScore
handDelta             = selfHandCount - opponentHandCount
lifeDelta             = selfLivesRemaining - opponentLivesRemaining
roundsDelta           = selfRoundsWon - opponentRoundsWon   // 仅辅助统计
selfFuturePower       = calculateKnownSelfFuturePower(selfHand, selfDiscard, leader, faction)
opponentVisiblePower  = opponentScore
opponentVisibleThreat = evaluateVisibleThreat(opponentBoard, opponentDiscard,
                                              opponentHandCount, faction, leader)
leaderDelta           = value(selfLeaderAvailable) - visibleValue(opponentLeaderAvailable)
carryoverDelta        = knownSelfCarryover - visibleOpponentCarryover
```

己方“有效手牌价值”不能只用数组长度：间谍可能净增手牌，召集可能一次打出多张同组卡，医生和阵营能力会产生未来资源，应按己方已知卡牌精确计算。

`opponentVisibleThreat` 只能使用公开信息做保守分级，例如“对手还有多少张牌”“场上是否已出现联结/召集结构”“领袖是否未使用”。它不得给对手虚构具体隐藏牌，也不得依赖历史胜率或 NPC 个体模型。

## 4. 推荐决策架构

### 4.1 一期总体结构

```text
当前可见状态
  -> 规则模拟器生成全部合法动作
  -> 执行强制规则（避免立即输局、对手已停牌、数学必败等）
  -> 逐个完整模拟己方动作的公开结算结果
  -> 计算即时净摆幅、资源保留、组合暴露和公开风险
  -> 选择综合评分最高的动作
  -> 若对手已停牌，改用已知状态获胜序列搜索
```

一期不采样对手隐藏手牌，不使用 expectimax、ISMCTS、历史日志或 NPC 行为模型。对手未停牌时，只模拟“己方当前动作结算完成”的结果，不继续虚构对手下一步会出哪张牌。对手可能反制所带来的风险，通过可见信息的保守惩罚表达，例如对手手牌较多且领袖未使用时，避免过早交出完整联结或号角。

### 4.2 动作结构

```text
Action
  type        // PLAY_CARD, USE_LEADER, PASS
  cardId
  targetRow
  targetCardId
  medicTargetId
  decoyTargetId
  leaderTarget
```

### 4.3 顶层伪代码

```pseudo
function chooseActionV1(state):
    actions = generateLegalActions(state)

    forced = applyForcedRules(state, actions)
    if forced != NONE:
        return forced

    if state.opponentPassed:
        plan = searchBestWinningSequenceFromKnownState(
            state,
            CONFIG.known_state_search.max_depth,
            CONFIG.known_state_search.max_actions_per_node
        )
        if plan != NONE:
            return plan.firstAction

    actions = removeIllegalOrStrictlyDominatedActions(state, actions)
    bestAction = PASS
    bestValue = evaluatePass(state)

    for action in actions:
        nextState = simulateOwnActionAndResolveVisibleEffects(state, action)

        value = evaluateVisibleState(nextState)
        value += immediateNetSwing(state, nextState)
        value += preservedResourceValue(state, action)
        value -= visibleCounterRisk(state, action)
        value -= overcommitPenalty(state, action)

        if value > bestValue:
            bestValue = value
            bestAction = action

    return bestAction
```

`visibleCounterRisk` 只能基于公开事实：对手剩余手牌张数、未使用领袖、已公开阵营能力、当前排结构和弃牌堆。它不能假设“对手一定有灼烧/天气/间谍”等具体隐藏牌。

### 4.4 终局和非终局估值

终局必须使用高权重离散值：

```text
胜利 = +100000
失败 = -100000
```

一期非终局使用固定、可配置的启发式评分，不依赖训练数据：

```text
V_visible(s) =
    w_life_delta              * life_delta
  + w_hand_delta              * hand_delta
  + w_normalized_score_delta  * normalized_score_delta
  + w_known_self_future_power * known_self_future_power
  + w_leader_delta            * leader_delta
  + w_known_carryover_delta   * known_carryover_delta
  + w_spy_potential           * spy_potential
  + w_combo_readiness         * combo_readiness
  - w_weather_exposure        * weather_exposure
  - w_scorch_exposure         * scorch_exposure
  - w_opponent_visible_threat * opponent_visible_threat
```

一期特征优先级：

```text
立即终局胜负 > 避免宝石归零 > 保持有效手牌与关键资源 > 当前轮胜负 > 当前分差
```

权重全部放在配置文件中，首版按本文建议值人工设置即可，不要求记录历史对局或训练参数。二期如引入对局数据，再单独训练或校准权重。

## 5. 硬规则与安全规则

以下规则优先于通用评分。发生冲突时按固定顺序处理：

```text
1. 合法性和规则结算
2. 避免立即输掉整场
3. 对手已停牌时，基于已知状态搜索能安全拿下该轮且保留资源最多的出牌序列
4. 已数学必败或当前轮可安全放弃时的停牌
5. 当前可见状态评分比较其余动作
6. 评分器异常时采用固定启发式优先级
```

### 5.1 对手已停牌

```pseudo
if opponentPassed:
    plan = searchBestWinningSequenceFromKnownState(
            state,
            CONFIG.known_state_search.max_depth,
            CONFIG.known_state_search.max_actions_per_node
        )

    if plan != NONE:
        return plan.firstAction

    if thisRoundCanBeLostWithoutLosingMatch:
        return PASS

    return actionWithMaximumReachableScore
```

所有能拿下该轮的计划都只基于已知状态计算，并按资源代价排序。若动作包含己方抽牌、怪物保留或史凯利格复活等游戏内随机效果，可对已知候选集合枚举分支或计算期望值；不得把对手未知手牌加入随机分支：

```text
1. 未来有效战力和组合价值损失最少
2. 不可恢复资源损失最少
3. 消耗的有效手牌价值最少
4. 溢出分数最少
```

不能把“出牌张数最少”放在绝对第一位，否则可能错误地用一张关键英雄替代两张低价值白板。普通阵营必须严格高于对手才能赢轮；尼弗迦德允许以平分赢轮。计划达到获胜条件后，默认以 `PASS` 结束；唯一允许继续展开的是诱饵等资源回收动作，且最终必须重新满足赢轮条件并以 `PASS` 结束。不得为增加无意义分数继续加码。

### 5.2 禁止主动放弃的情况

```text
- `selfLivesRemaining == 1`，且当前轮失败或普通平分会使己方宝石归零。
- 当前可通过合理资源投入赢轮，且没有更高胜率的特殊例外。
- 对手已经停牌，而己方可以低成本超过或追平取胜。
```

### 5.3 应立即停牌的情况

满足下列任一条件时优先停牌：

```text
- 当前轮可放弃，且追分至少需要两张高价值牌，预计会导致后续轮资源劣势。
- 当前可达最高分仍不能满足己方阵营的赢轮条件；普通阵营需要严格超过，尼弗迦德达到平分即可。
- 己方已领先且当前轮可以放弃；根据当前分差和对手剩余手牌张数，继续加码的收益明显低于保留资源。此判断只使用张数和分差，不假设对手持有具体卡牌。
- 继续出牌只会形成无意义溢出。
```

### 5.4 严格过滤与风险惩罚

只直接过滤非法动作和可证明被另一动作严格支配的动作。下列动作通常应施加较大风险惩罚，而不是在搜索前无条件删除，因为它们偶尔可用于诱敌、调整灼烧最高点或决胜交换：

- 净效果暂时为负的天气。
- 灼烧造成己方损失大于等于敌方损失。
- 诱饵换回低价值白板单位。
- 在非决胜轮过早拆出完整爆发组合。

以下动作可直接过滤：

- 号角打到无合法受益目标的排。
- 医生没有任何合法复活目标。
- 在对手已停牌且当前轮已经安全获胜时，继续投入只增加点数、却不能回收高价值单位或改善后续资源的动作。若诱饵等动作能提高后续资源且执行后仍可确保赢轮，则不得过滤。
- 违反卡牌目标、阵营、排位或停牌状态的动作。

## 6. 分轮策略

### 6.1 第一轮

默认目标：建立牌差、保留高价值资源，并根据对手已经公开投入的资源决定是否继续；不要求必须赢。

动作优先级：

```text
1. 低战力间谍
2. 用诱饵回收敌方间谍并反打
3. 低风险、低组合价值单位
4. 不破坏后续组合、未来价值较低的普通单位
5. 必要的控制牌
6. 最后才是英雄、完整紧密联结、号角或大规模召集
```

第一轮主动放弃条件示例：

```text
- 间谍已经建立至少 2 张有效手牌优势。
- 对手为领先已经比己方多投入至少 2 张牌。
- 继续追分会消耗完整组合或关键控制牌。
- 对手怪物已经打出一组或多组召集，可让这些单位在轮末进入弃牌堆。
```

对北方领域需要提高弃轮门槛，因为对方赢轮后会额外抽一张牌。

### 6.2 第二轮

若己方赢了第一轮：

- 可以低成本逼迫对手消耗资源。
- 若对手为怪物且有跨轮保留单位，直接停牌可能让对手不花手牌就赢轮，应避免无条件“干过”。
- 若对手为史凯利格，应考虑第二轮继续施压，避免让其以完整资源进入第三轮并触发两张复活。
- 若继续施压会消耗自己的决胜组合，应尽早停牌。

若己方输了第一轮：

- 当前轮必须确保不输。
- 对手停牌后只用最低成本超过。
- 不要为扩大领先浪费号角、英雄或完整联结。

### 6.3 第三轮

第三轮没有后续资源价值，策略改为最大化最终净点数和控制收益：

- 英雄、高点牌和核心组合全部可投入。
- 对手未停牌且仍有手牌时，先使用未来价值较低的安全单位；只有当前轮必须取胜或组合收益足够高时，再完成联结或号角爆发。
- 天气、灼烧尽量延后到对手目标排成型，或对手已经停牌后使用。
- 史凯利格第三轮复活、怪物跨轮保留必须在出牌前加入当前场面估值。

## 7. 卡牌能力的程序化策略

### 7.1 间谍

间谍价值近似为：

```text
spyValue = expectedValue(draw 2 cards)
           - strengthGivenToOpponent
           + futureMedicReuseValue
           - currentRoundLossRisk
```

规则：

- 同样抽两张时，低战力间谍优先。
- 第一轮和第二轮早段价值最高。
- 决胜轮末段若送出的点数可能直接导致无法追上，应通过模拟判断，不得机械使用。
- 若牌库不足两张，抽牌收益按实际剩余牌数计算。

### 7.2 诱饵

目标优先级：

```text
1. 对手打到己方场上的间谍
2. 已触发、且弃牌堆存在高价值目标的医生
3. 可再次触发高收益效果的 Villentretenmerth 等单位
4. 对手已停牌时，回收己方可留给后续轮的高价值单位
5. 其他高价值入场单位
```

诱饵目标评分：

```text
decoyTargetValue = replayTriggerValue
                   + futureCardValue
                   + rescuedStrengthForLaterRound
                   - currentRoundStrengthLost
```

### 7.3 医生

复活目标应通过模拟后净收益排序，默认优先级：

```text
1. 间谍
2. 能继续复活链的医生
3. 能补齐紧密联结的单位
4. Villentretenmerth 或其他高收益入场单位
5. 当前轮所需的最高有效战力单位
```

第一轮弃牌堆没有高价值目标时，不要过早打医生。被复活单位必须完整触发其合法入场效果。

### 7.4 灼烧

程序必须模拟灼烧后的整块棋盘，而不是只比较一张卡。

```text
scorchNetSwing = enemyDestroyedCurrentPower
                 - selfDestroyedCurrentPower
                 + enemyComboValueDestroyed
                 - selfComboValueDestroyed
```

建议初始阈值：

```text
非决胜轮：scorchNetSwing >= 8 才主动使用
决胜轮：  scorchNetSwing >= 4，或使用后可直接获得胜利
```

阈值只是初始参数，应通过实测调整。

额外规则：

- 若敌方多张并列最高，灼烧价值会显著增加。
- 己方联结或号角强化后可能成为最高目标，必须先模拟。
- Villentretenmerth 只在敌方近战排当前已满足触发条件且净收益足够时使用；若之后公开场面再次形成合法高收益目标，再评估是否用诱饵复用，不预判对方一定会继续铺场。

### 7.5 天气和晴天

天气净收益：

```text
weatherNetSwing = enemyPowerLossAfterFullRecalculation
                  - selfPowerLossAfterFullRecalculation
```

建议初始条件：

```text
weatherNetSwing >= 6
```

使用原则：

- 尽量等敌方目标排已经投入多张非英雄单位。
- 对手已经停牌时使用更安全。
- 对手为怪物、刺骨冰霜已在己方手中且敌方近战排已形成高净收益目标时，优先评估刺骨冰霜。
- 对手为北方领域、暴雨已在己方手中且敌方攻城排已形成高净收益目标时，优先评估暴雨。
- 松鼠党需根据实际近战/远程分布选择，不应只按阵营名称硬编码。
- 晴天尽量保留到天气实际造成较大己方损失时，不要过早清除低影响天气。

### 7.6 指挥号角

对每个可选排计算：

```text
hornGain(row) = rowPowerAfterHorn - rowPowerBeforeHorn
```

选择 `hornGain` 最大的合法排。优先使用场景：

- 第三轮；
- 对手已停牌；
- 使用后可用最少资源赢下必须取胜的轮；
- 天气和灼烧风险已经明显降低。

不要因为某排单位多就直接使用，英雄不会获得号角收益。

### 7.7 紧密联结

- 组合未齐时，尽量不在非决胜轮暴露关键组件。
- 对手未停牌且仍有手牌时，完整联结增加公开风险；非必须取胜时优先保留组件，必须取胜时按当前净增益决定是否组成联结。
- 完整组合价值必须由规则模拟器计算。
- 联结后的当前战力可能让整组单位成为灼烧目标。

### 7.8 召集

牌组和起手牌已经确定，策略模块只处理“当前是否打出召集牌”：

- 先用规则模拟器计算该召集牌会从己方手牌和牌库实际拉出哪些单位，以及结算后的总增益。
- 非决胜轮若准备主动放弃，不应打出会一次消耗大量未来战力的召集牌。
- 对手控制牌尚未公开、对手手牌仍多时，召集铺满单排会提高天气和单位型灼烧的公开风险，应增加过度投入惩罚。
- 决胜轮或对手已停牌时，按完整结算后的净增益评估，不因“召集”标签机械保留。

### 7.9 英雄

英雄适合：

- 最后一轮稳定输出；
- 天气已经覆盖普通单位所在排；
- 需要不受灼烧影响的安全追分；
- 当前公开场面存在天气或灼烧风险时，作为不受这些效果影响的稳定追分手段。

英雄不能被号角等常规增益强化，也不能被医生复活，因此其“当前稳定点数”高，但“组合和循环价值”低于某些普通功能牌。

### 7.10 领袖能力

领袖能力应作为动作纳入模拟，不要固定在某轮使用。常见原则：

- 清天气领袖：保留到己方天气净损失达到阈值，或能直接赢轮。
- 号角类领袖：与普通号角相同，选增益最高排，并避免重复效果。
- 取消对方领袖：当对方领袖预期收益高于阈值时使用。
- 搜索/打出指定牌的领袖：按实际可检索集合和未来资源计算，不要只看即时点数。

## 8. 当前手牌的动态价值标注

牌组、领袖和起手牌由外部系统确定。策略模块只为当前手牌计算“现在打出”和“留到后续”的价值，不提出任何增删牌建议。

每张手牌可动态计算：

```text
immediateGain       // 当前完整结算后的己方增分减去敌方增分
futureResourceValue // 留到后续轮的独立战力、组合价值和控制价值
comboReadiness      // 当前是否能完成联结、召集、号角、医生等组合
replayValue         // 被诱饵回收或被医生复活后的再次触发价值
controlValue        // 天气、灼烧、晴天等对当前公开场面的控制收益
exposureRisk        // 打出后遭天气、灼烧或导致过度投入的公开风险
```

出牌成本建议统一为：

```text
playCost = futureResourceValue
           + comboBreakCost
           + irreversibleUseCost
           + exposureRisk
           - immediateGain
           - controlValue
```

非决胜轮优先选择 `playCost` 较低且能推进本轮目标的动作；决胜轮降低 `futureResourceValue` 权重，把可兑现的即时收益放到更高优先级。该计算只针对已经拿到的牌，不涉及牌组设置或起手调度。

## 9. 针对对手阵营的规则

### 9.1 对怪物

```text
提高：刺骨冰霜、灼烧、Villentretenmerth 的保留价值
降低：己方近战排号角前的过早投入
策略：若对手已经在可放弃轮次公开打出召集铺场，则重新计算后优先考虑停牌；第三轮保留当前手中已有的控制牌
注意：怪物跨轮保留单位，第二轮不能机械干过
```

### 9.2 对尼弗迦德

```text
诱饵优先留给敌方间谍
计算轮次胜负时应用“平分由尼弗迦德获胜”
只有当对方已经公开医生能力并实际从弃牌堆复活间谍后，才把已经发生的抽牌计入对手手牌数；不得预判其隐藏手牌中有医生
若自己不是尼弗迦德，对手停牌时必须严格超过其分数
```

### 9.3 对北方领域

```text
提高暴雨和灼烧的价值
重点监控攻城排和紧密联结
不要让其用一张低牌赢下弃轮并再抽一张，除非己方仍有明确牌差收益
估计对方赢轮后手牌数时加上阵营额外抽牌
```

### 9.4 对松鼠党

```text
根据近战/远程实际分布选择天气
召集在可放弃轮次出现时可考虑停牌，让整组进入弃牌堆
若对方已经在当前对局公开并打出医生，只根据实际发生的复活更新场面和弃牌堆；不得预判其隐藏手牌中仍有医生
只根据已经落位的敏捷单位和当前两排分布判断天气收益，不猜测对手尚未公开的敏捷牌
```

### 9.5 对史凯利格

```text
第三轮开始前估计其弃牌堆中随机复活两张的期望值和上界
若己方赢第一轮且资源允许，第二轮适度施压，避免对方零成本进入强势第三轮
天气或灼烧尽量在第三轮复活结算后使用
对方弃牌堆中的高价值组合牌应提高其未来战力估计
```

## 10. 一期的对手信息处理

### 10.1 只使用公开信息

一期不建立对手隐藏手牌概率，不采样未知牌，也不读取历史对局。允许使用的对手信息只有：

```text
opponentFaction
opponentLeader / opponentLeaderAvailable
opponentHandCount
opponentBoard
opponentDiscard
opponentPassed
opponentRevealedCards
```

对手手牌中的具体牌和牌库内容统一视为 `UNKNOWN`。任何规则不得写成“假设对手有某张牌后再决定”。

### 10.2 保守风险等级

未知信息只转换为粗粒度风险，不转换为具体卡牌概率：

```text
LOW：   对手已停牌，或手牌为 0
MEDIUM：对手仍有少量手牌，但公开场面尚未形成明显组合
HIGH：  对手手牌较多、领袖未使用，或公开场面已经形成联结/召集/单排堆叠
```

风险等级只影响“是否过早交出关键组合”和“是否继续过度投入”，不能替代规则模拟器的确定性结算。

### 10.3 一期不启用 NPC 行为预测

一期不假设 NPC 会过度投入、提前灼烧、错误使用天气或浪费控制牌。只允许对已经发生的公开动作作出响应：

```text
对手已经打出召集铺场 -> 重新计算当前轮是否值得继续，若可放弃则允许立即停牌
对手已经使用灼烧     -> 更新场面与弃牌堆，不因此推断其是否还有第二张灼烧
对手已经使用天气     -> 根据己方当前实际损失评估晴天或清天气领袖
对手已经停牌         -> 启动已知状态获胜序列搜索
```

基于 NPC 常见短视行为的诱骗策略全部移入二期。

### 10.4 二期扩展，不属于一期实现

二期可再增加：历史对局日志、对手隐藏牌概率、NPC 个体画像、停牌概率模型、expectimax/ISMCTS 和自动调参。本文一期逻辑不能依赖这些能力才能运行。

## 11. 最优获胜序列搜索

当对手已停牌时，执行基于己方已知牌和公开场面的有限深度搜索，而不是按单卡点数或出牌张数贪心。目标是在拿下该轮的候选序列中，选择保留后续有效资源最多、溢出最少的方案。

```pseudo
function searchBestWinningSequenceFromKnownState(state, MAX_DEPTH, MAX_ACTIONS_PER_NODE):
    candidates = []
    queue = priorityQueue(orderBy = lowKnownResourceCostFirst)
    queue.push(state, emptyPlan, depth = 0)

    while queue not empty:
        node = queue.pop()

        secured = hasSecuredRoundAgainstPassedOpponent(node.state)
        if secured:
            finalState = simulate(node.state, PASS)
            candidates.add(
                plan = node.plan + PASS,
                resourceScore = evaluateKnownResourcesAfterRound(finalState),
                overkill = calculateOverkill(finalState)
            )

        if node.depth >= MAX_DEPTH:
            continue

        if secured:
            actions = legalResourceRecoveryActions(node.state)
        else:
            actions = legalNonPassActions(node.state)

        actions = rankByKnownResourceCost(actions)
        for action in actions.takeFirst(MAX_ACTIONS_PER_NODE):
            next = simulateOwnActionAndResolveVisibleEffects(node.state, action)
            queue.push(next, node.plan + action, depth = node.depth + 1)

    if candidates.empty:
        return NONE

    return argmax(candidates,
                  resourceScore,
                  tieBreakBy = [lowOverkill, fewerIrreversibleResourcesUsed])
```

如果当前游戏随机种子可读取，模拟器直接使用该种子；如果不可读取，`simulateOwnActionAndResolveVisibleEffects` 应返回规则允许的随机结果分支，并按游戏定义概率汇总 `resourceScore`。这些分支只能来自规则允许的公开候选集合，例如己方已知剩余牌、公开弃牌堆或怪物当前公开场上的保留候选，不能包含对手隐藏手牌或未知牌库猜测。

必须展开组合动作，因为：

- 一张医生可能同时复活另一张单位；
- 一张召集牌可能打出多张单位；
- 诱饵本轮降分但能让下一步产生更大价值；
- 号角收益取决于整排；
- 天气和灼烧会重算双方多张牌。

## 12. 第一版规则引擎的动作优先级

如果暂时不实现搜索，可使用以下安全基线：

```pseudo
function chooseByBaseline(state):
    if opponentPassed:
        if hasSecuredRoundAgainstPassedOpponent(state):
            recovery = bestResourceRecoveryActionThatStillSecuresRound(state)
            if recovery != NONE:
                return recovery
            return PASS

        action = lowestKnownResourceCostActionTowardWinningScore(state)
        if action != NONE:
            return action
        if roundCanBeLostWithoutLosingMatch(state):
            return PASS
        return maximumReachableScoreAction(state)

    if mustAvoidImmediateMatchLoss(state):
        return highestMatchSurvivalValueAction(state)

    if finalRound(state) or mustWinCurrentRound(state):
        return highestSimulatedGainAction(state)

    if receivedOpponentSpy(state) and haveDecoy(state):
        return Decoy(bestOpponentSpyTarget(state))

    if earlyRound(state) and haveLowStrengthSpy(state)
       and spyDoesNotCauseMatchLoss(state):
        return play(lowestCostSpy(state))

    if haveMedic(state) and discardHasHighValueTarget(state):
        return playMedic(bestSimulatedTarget(state))

    if canUseScorchWithNetSwingAboveThreshold(state):
        return playScorch()

    if canUseWeatherWithNetSwingAboveThreshold(state):
        return playWeather(bestRow(state))

    if shouldPassByRoundBudget(state):
        return PASS

    return play(lowestFutureValueSafeUnit(state))
```

注意：这只是基线。真实高胜率版本应由搜索比较所有合法动作，而不是永远按该顺序执行。

## 14. 一期决策结果输出

一期不建立跨对局历史库，也不根据过去对局调整策略。为了便于排查单次决策，可以返回本次决策解释，但无需持久化：

```text
chosenAction
forcedRuleApplied
visibleStateScoreBefore
visibleStateScoreAfter
immediateNetSwing
preservedResourceValue
visibleCounterRisk
overcommitPenalty
alternativeActionsTop3
```

要求：

1. 所有字段只来自当前对局的公开状态和己方已知信息。
2. 不输出或保存对手隐藏手牌猜测。
3. 相同输入状态与相同随机种子必须得到相同动作，便于复现。

5. 跨对局胜率统计、NPC 个体参数和自动调参属于二期，不影响一期策略模块。

## 15. 验收测试用例

所有随机效果测试必须支持固定随机种子，以便复现怪物保留、史凯利格复活和随机抽牌结果。

### 用例 0：普通阵营平分

```text
双方均不是尼弗迦德，且本轮同分。
期望：双方各失去 1 枚生命宝石；程序能处理双方同时归零时的目标版本终局结果。
```

### 用例 1：对手停牌，最低成本超过

```text
对手 20 分并已停牌；己方 17 分。
手牌：4 点白板、10 点英雄、号角。
期望：出 4 点白板至 21 分，然后停牌；不出英雄，不用号角。
```

### 用例 2：尼弗迦德平分取胜

```text
己方为尼弗迦德；对手 20 分并停牌；己方 16 分。
手牌有 4 点和 6 点单位。
期望：使用 4 点达到 20 分并赢轮，不使用 6 点牌。
```

### 用例 3：诱饵回收敌方间谍

```text
对手把间谍打到己方场上；己方有诱饵。
期望：若不会立刻输掉必须取胜轮，优先诱饵回收该间谍，并在合适时机反打抽牌。
```

### 用例 4：灼烧并列单位

```text
敌方有三张当前战力 10 的非英雄；己方最高为 8。
期望：灼烧评价包含摧毁敌方三张 10，而非只计算一张。
```

### 用例 5：灼烧自伤

```text
敌方最高 10 一张；己方也有两张当前战力 10。
期望：对灼烧施加高风险惩罚并通常不选择；但动作仍保留在合法动作集中，决胜轮若能避免立即输局可被评分器选中。
```

### 用例 6：天气影响双方

```text
敌方近战天气前损失 24；己方近战天气前损失 20。
期望：不能只看到敌方损失 24 就出天气，应按当前公开局面计算双方净摆幅；不得假设对手隐藏手牌中有晴天。
```

### 用例 7：医生复活间谍

```text
弃牌堆有间谍和 10 点白板；牌库仍有足够卡。
期望：若当前轮送分风险可接受，复活间谍通常优于 10 点白板。
```

### 用例 8：召集牌的当前出牌判断

```text
当前手牌有召集触发牌，规则模拟器显示打出后会额外拉出同组单位；本轮准备主动放弃。
期望：把完整召集消耗计入未来资源损失，通常不在该轮打出；不得执行换牌或修改牌组。
```

### 用例 9：怪物跨轮保留

```text
己方赢第一轮；怪物第二轮开始时已有保留单位。
期望：不能默认直接停牌会迫使对方消耗一张手牌。
```

### 用例 10：史凯利格第三轮

```text
第二轮结束时，史凯利格弃牌堆有多张高点单位。
期望：第三轮估值包含随机复活两张的期望值与高分风险。
```

### 用例 11：不可赢轮立即停牌

```text
己方当前及全部手牌的最高可达分仍低于对手，对手未停牌，当前轮可放弃。
期望：立即停牌，不继续浪费资源。
```

### 用例 12：第一轮避免过度投入

```text
己方必须再交完整联结组合和号角才能追上；对手已比己方多用两张牌；己方仍有 2 枚生命宝石。
期望：优先停牌，把组合留到后续轮次。
```

### 用例 13：天气、联结、士气和号角顺序

```text
构造同一排同时存在天气、两张同名联结、士气和号角的固定局面。
期望：程序结果与目标游戏版本截图或人工记录逐卡一致，而不是只比较最终总分。
```

### 用例 14：召集来源区域

```text
同一召集组分别在手牌、牌库和弃牌堆各放置副本。
期望：只拉取目标版本允许的区域，弃牌堆副本不得被错误召集；该规则标记为 VERIFIED_IN_TARGET_BUILD。
```

### 用例 15：医生连锁与空牌库抽牌

```text
医生复活医生，再由第二张医生复活间谍；牌库只剩 1 张牌。
期望：所有合法入场效果按顺序结算，间谍最多只抽到实际剩余牌数，不出现负牌库或重复卡。
```

### 用例 16：单位型灼烧

```text
敌方近战排达到 Villentretenmerth 的触发阈值，同时其他排存在更高单位。
期望：只按该卡定义处理敌方近战排，不误用通用灼烧的全场最高目标。
```

### 用例 17：领袖能力与停牌状态机

```text
对手已停牌，己方使用领袖即可安全赢轮；另构造己方已停牌但仍尝试出牌的状态。
期望：前者能选择合法领袖动作并随后停牌；后者不得生成任何出牌或领袖动作。
```

### 用例 18：关键英雄与两张低价值牌

```text
对手已停牌；一张关键英雄或两张低价值白板均可拿下本轮，按己方已知资源评分，保留英雄的后续资源价值更高。
期望：选择两张低价值牌方案，证明搜索不是绝对按“张数最少”优化。
```

### 用例 19：一期不读取对手隐藏牌

```text
构造两个状态：双方公开场面、手牌张数和所有一期输入完全相同，只在测试夹具中给对手放入不同的隐藏牌。
期望：一期策略输出完全相同，证明隐藏牌内容没有进入决策输入。
```

### 用例 20：领先后的诱饵资源回收

```text
对手已停牌；己方领先 8 分，场上有一张 5 点高价值入场单位，手中有诱饵。
期望：搜索比较“立即停牌”和“诱饵回收后仍领先再停牌”，若后者能确保赢轮且提高后续资源，选择诱饵；不得继续打纯加分牌。
```

## 16. 实施顺序

### 阶段 A：保证规则正确

1. 完成卡牌和区域状态模型。
2. 完成所有合法动作生成。
3. 完成统一的效果结算和分数重算。
4. 用第 15 章测试验证规则层。

### 阶段 B：一期可见状态策略

1. 实现间谍、诱饵、医生、天气、灼烧、号角和领袖的当前动作完整模拟。
2. 实现停牌预算、禁止过度投入和不可赢轮立即停牌。
3. 实现当前手牌的动态价值标注。
4. 实现阵营针对规则，但只在相关牌已经位于己方手牌或对手威胁已经公开时生效。
5. 实现固定参数的可见状态评分器，不读取历史对局。

### 阶段 C：一期已知状态搜索

1. 生成完整合法动作，包括目标、排位、诱饵目标和医生目标。
2. 对手已停牌时，在 `max_depth` 和 `max_actions_per_node` 限制内搜索候选获胜序列，选择资源保留最多的方案。
3. 对医生链、召集、诱饵复用、号角、天气和灼烧展开完整组合动作。
4. 性能不足时限制每节点候选动作数，并使用动作合并和状态缓存；如后续改为标准 beam search，需按搜索深度保留全局前 K 个节点。
5. 输出单次决策解释，确保相同状态可复现。

### 阶段 D：二期可选扩展，不属于本次实现

1. 跨对局日志与胜率统计。
2. 对手隐藏牌信念状态和采样。
3. NPC 个体停牌与出牌模型。
4. expectimax/ISMCTS。
5. 自动调参和 A/B 测试。
